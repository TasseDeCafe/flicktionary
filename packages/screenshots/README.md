# @flicktionary/screenshots

> **Status: reference.** How to run the automated product-screenshot pipeline in this folder. Design history in `old-docs/automated-screenshots.md`.

Playwright scripts that seed a demo account with curated data, drive the real extension + web app against the dev-tunnel stack, and write up-to-date product screenshots — raw 1280×800 captures in `shots/` (Chrome Web Store size) and refreshed landing assets in `apps/landing/src/assets/`.

## One command

```bash
pnpm --filter @flicktionary/screenshots shoot:all
```

Runs the full pipeline: `seed → shoot:extension → seed → shoot:web → postprocess`. Seed runs twice because the YouTube study sessions only exist after the extension script has visited the videos; the second pass fills them with vocabulary, seeds the card chat, and shapes practice state.

Prereqs:

- Dev tunnel running (`pnpm dev` — web + backend + dev-tunnel Supabase). The backend must be the real one (enrichment worker + Anthropic key) since all card/gloss/chat content is generated by the live pipeline.
- A dev-config extension build: `pnpm --filter @flicktionary/extension build:dev` (must be the Doppler-wrapped script — a bare `wxt build` bakes in no env and pairing fails with `Missing required env var WXT_PUBLIC_API_HOST`).
- Once: `pnpm --filter @flicktionary/screenshots playwright:install` (downloads Chromium).

## The pieces

| Script | What it does |
| --- | --- |
| `seed` | Idempotent data seeding via the real API + targeted SQL. Creates/onboards the demo account (`demo@flicktionary.app`), imports the text sources, adds curated highlights to every existing session (real enrichment → real cards), seeds one live card-chat exchange, promotes some facets to due review flashcards, and waits for bank exercises to be ready. |
| `shoot:extension` | Captures the in-video surfaces on the two curated YouTube videos (German with a manual `de-DE` track, Spanish ASR): paired popup, subtitle overlay, hover-gloss popover, saved popover, and the German multi-word phrase selection (drag across `verzeiht mir`). Saving the hero word/phrase is what creates the YouTube sessions the seed builds on. Idempotent: already-saved targets are unsaved (right-click toggle) and re-saved so every run captures the same fresh state. |
| `shoot:web` | Captures the web screens against the seeded account: sessions list, video reader with the gloss sheet open, text reader, session vocabulary, focus view with chat, practice exercise in the correct-answer state (the right MC option is looked up in `practice_exercises.payload`), flashcard front/back, vocabulary tab. |
| `postprocess` | Copies mapped captures over the existing `apps/landing/src/assets/*.png` names (drop-in refresh) and writes `<name>-cropped.png` variants per the crop rects in the manifest. |

`src/manifest.mjs` is the single place to curate what the screenshots show: demo account, videos, words + timestamps, vocabulary lists, text sources, chat question, practice shaping, and the capture → landing-asset mapping with crops. After a curation change (new video, new word list), run `pnpm --filter @flicktionary/screenshots seed -- --reset` first — it wipes the demo account's sessions/vocabulary/practice state (auth user, onboarding, and pairing survive) so stale content doesn't linger in the shots.

## Recipes worth knowing (hard-won)

- **Web sign-in without email round-trips.** Local Supabase admin `generateLink({type:'magiclink'})` at `http://127.0.0.1:34321`, then drive `/login/email/verify?token_hash=…` and click `Verify`. The seed script goes one step further and calls `verifyOtp` directly for a Bearer token — no browser at all.
- **Admin-created users need an extra row.** `auth.admin.createUser` alone breaks the backend: `public.users` is normally inserted by the web signup flow, so the seed mirrors `users-repository.insertUser`. (The email itself needs nothing extra — the auth middleware reads it from the token's top-level claim, which GoTrue mints from `auth.users.email`.)
- **Skip the track dialog; seed auto-sync.** Write `chrome.storage.local.streamingLastLanguagesSynced = {'www.youtube.com': ['<lang>']}` via the service worker before opening the video. Use the exact YouTube track code — `de-DE` for the manual German track; plain `de` would match the ASR track (lowercase words, re-chunked timings).
- **uBlock Origin Lite rides along.** Downloaded automatically into `vendor/ubolite` and loaded next to the Flicktionary extension, which kills pre-roll/mid-roll ads (mid-rolls otherwise fire on every seek). Because two extensions mean two service workers, the Flicktionary one is identified by probing for `popup-ui.html`.
- **Capture only settled UI.** Gloss popovers mount before their content: wait for `[data-slot="skeleton"]` to disappear and the text to stop changing. YouTube player controls fade ~3s after the last mouse move — wait them out. Force YouTube's own caption renderer off right before capturing (it can switch on when the track syncs).
- **Multi-word selection** is a left-button drag: `mouse.down()` on the first word span, `mouse.move()` through each following `[data-word]` span, `mouse.up()` — the chunk gloss opens pinned. Overlay shadow roots are `mode:'open'`, so Playwright locators pierce them. Pick a phrase on the **first rendered subtitle row**: the popover anchors above the selection, so phrases on lower rows end up hidden behind it.
- **Curate frame targets, not just words.** Some videos burn explanation cards into the frame right under the subtitles — check the window you capture in (the current German video is clean between 0:15 and 1:00).
- The persistent `user-data/` profile keeps sign-in, pairing, and consent dismissal across runs. It is account-stamped: switching `SCREENSHOT_EMAIL` wipes it automatically; `-- --fresh` wipes it manually.

Knobs (env vars): `SCREENSHOT_EMAIL`, `SCREENSHOT_WEB_URL`, `SCREENSHOT_API_URL`, `SCREENSHOT_SUPABASE_URL`, `SUPABASE_CONNECTION_STRING`.

## Store uploads

Chrome Web Store listing screenshots must be exactly 1280×800 — use the raw `shots/*.png`. The store upload itself stays manual (its publish API cannot update listing screenshots).

`user-data/`, `shots/`, and `vendor/` are gitignored.
