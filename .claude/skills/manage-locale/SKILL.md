You are adding, removing, or toggling a UI locale across the monorepo. This only concerns the **UI language** (Lingui catalogs). It does NOT concern target/native study languages — those live in `packages/core/src/constants/supported-languages.ts` and follow their own rules.

The UI is driven by Lingui. A locale is "live" when all of the following are wired:

1. `packages/i18n/src/i18n-config.ts` — locale constant exported and present in `i18nConfig.locales`. This array drives the `Locale` type, so it's the source of truth.
2. `lingui.config.mjs` — locale listed in the root `locales` array. This drives `lingui extract` / `lingui compile` and the `pnpm translate` script.
3. `packages/i18n/locales/<locale>/messages.po` — catalog file exists. Generated by `lingui extract`; populated by `pnpm translate` (calls Claude) or by hand.
4. `apps/web/src/lib/i18n/i18n.ts` — static import of the `.po` catalog, entry in the `catalogs` map, branch in `getBrowserLocale`.
5. `apps/native/src/lib/i18n/i18n.ts` — same shape as web (Metro requires static imports, no dynamic `import()` with template literals).
6. `apps/native/src/stores/locale-store.ts` — branch in `getDeviceLocale`.

## Removing / disabling a locale

Prefer **commenting out** rather than deleting — the user typically wants to re-enable later, and leaving the `.po` file intact preserves existing translations.

In each of the six touchpoints above, comment out the locale-specific lines using `//` or `/* … */`. Leave `packages/i18n/locales/<locale>/messages.po` on disk untouched.

Order doesn't matter, but if you do them in this order the typechecker stays happy throughout:

1. Comment out the import + `catalogs` map entry + detection branch in `apps/web/src/lib/i18n/i18n.ts`.
2. Same in `apps/native/src/lib/i18n/i18n.ts`.
3. Comment out the `SPANISH_LOCALE` / `POLISH_LOCALE`-style import and detection branch in `apps/native/src/stores/locale-store.ts`.
4. Comment out the locale from `i18nConfig.locales` in `packages/i18n/src/i18n-config.ts` (and optionally the `*_LOCALE` constant if no other place still needs it).
5. Comment out the locale from the `locales` array in `lingui.config.mjs`.

Then run `pnpm --filter @flicktionary/i18n --filter @flicktionary/web --filter @flicktionary/native check:types` to confirm nothing broke.

## Adding / enabling a locale

For a brand-new locale (e.g. German `de`):

1. In `packages/i18n/src/i18n-config.ts`: add `export const GERMAN_LOCALE = 'de'` and append it to `i18nConfig.locales`.
2. In `lingui.config.mjs`: add `'de'` to the `locales` array.
3. From the repo root, run `pnpm lingui extract --clean` to generate `packages/i18n/locales/de/messages.po`. Then run `pnpm translate` to populate it via Claude, or commit the empty file and translate later.
4. In `apps/web/src/lib/i18n/i18n.ts`: add the static import, the `catalogs` entry, and a branch in `getBrowserLocale`.
5. In `apps/native/src/lib/i18n/i18n.ts`: same — static import + `catalogs` entry. (No detection happens here; that's in the locale store.)
6. In `apps/native/src/stores/locale-store.ts`: add the import and the detection branch in `getDeviceLocale`.
7. Run typecheck (`pnpm --filter @flicktionary/i18n --filter @flicktionary/web --filter @flicktionary/native check:types`).

Re-enabling a previously commented-out locale: same as above but you're un-commenting instead of writing fresh code, and the `.po` file is already on disk.

## Notes

- The detection branches use a simple `if (browserLang === X) return X` ladder, falling through to `ENGLISH_LOCALE`. Keep the same shape — don't introduce a map or Object lookup.
- The `Locale` type is derived from `i18nConfig.locales`, so commenting an entry out of that array immediately removes it from the type. Any code still referencing the locale will fail to typecheck — that's the signal to find missed touchpoints.
- Don't touch `packages/core/src/constants/supported-languages.ts`. That's the list of **study** languages users can learn, unrelated to UI locale.
- Don't touch backend files that reference `'es'` / `'pl'` (e.g. `language-instructions.ts`, `text-segments-repository.ts`). Those are study-language target codes, not UI locales.
